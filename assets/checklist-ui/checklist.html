Shared components with issues

These are used on several screens, so the scan flags them on every one. Log a problem with one of them once, naming the component (e.g. close button has no name (StyledModal)). Only fail another screen for it if you actually see or hear it there.

How it works

  • Pick a screen on the left, then the iOS or Android tab on the screen, and work down its checks. The tab you pick stays selected as you move between screens. Setup in each tab says which device settings to have ready.
  • Mark each check Pass, Fail, or N/A. Click the active button again to clear it.
  • Quicker: mark only the fails and N/As, then click Pass the rest of this screen at the bottom once you've tested everything. Checks the scan already failed aren't passed; confirm those yourself.
  • On a fail, describe each problem and pick a severity. The first issue goes on the check's line; the rest go on indented lines below it.
  • Scan found issues · not reviewed yet: the code scan already failed this check, and that finding is in the report. Test the screen anyway, then click Fail (adding anything else you found) to mark it reviewed, or change the mark if the scan is wrong.
  • Shared components (button at the top) lists components used on many screens that the scan found problems in. Log each problem once instead of on every screen.
  • ⚑ High/Medium: what the code scan found in this screen's code. The severity is fixed for each scan rule (how much that kind of problem usually gets in the way), not judged for this screen; pick your own when you log an issue. ⚑ Verify: the scan can't judge it, so check by hand. Full details are in scan-details.md.
  • Can't reach a screen (no test account, feature off, crashes)? Tick Blocked under its name and say why. Blocked screens are listed in the report and the PDF.
  • A screen passes when every check is Pass or N/A, and fails if any check fails or it has an Other issue.
  • Everything is written to checklist.md in the toolkit's format, so you can also edit the file by hand. When you're done, run npx bt-a11y report.

Keyboard

  • P Pass and N N/A, then move to the next check
  • F Fail and jump to the issue field. Enter goes to the next check, Esc back to the buttons
  • U clear the mark
  • J / K next / previous check
  • ] / [ next / previous screen
  • ← / → on the platform tabs switch between iOS and Android

Saving

Chrome and Edge write to the .md file as you go. If the file changes on disk while it's open here (for example, you re-run npx bt-a11y or edit it in VS Code), saving stops and asks what to do. In other browsers, your work stays in this browser until you download it.
